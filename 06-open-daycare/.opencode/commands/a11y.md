---
description: Revisa y corrige accesibilidad WCAG 2.2 AA en archivos, carpetas o URLs (externas en solo-reporte).
agent: accessibility-check
---

Revisa y aplica WCAG 2.2 AA en los targets indicados: `$ARGUMENTS`.

Aplica el flujo completo del agente accessibility-check:

1. Clasifica cada target: archivo/carpeta local (modo fix), URL de este proyecto (auditar con Playwright → mapear al código → fix) o URL externa (solo reporte con recomendaciones, nunca editar). **Ojo: una URL externa no tiene por qué ser React** (puede ser Vue, Angular, WordPress, HTML plano, ...) — su auditoría es agnóstica de framework.
2. Consulta con Context7 la documentación oficial actual antes de juzgar cualquier categoría:
   - WCAG/WAI-ARIA → fuentes W3C/WAI oficiales (siempre, aplica a cualquier target)
   - React → `/reactjs/react.dev` (sección accessibility) **solo si hay targets locales** de este proyecto; nunca para URLs externas
   Temas típicos: "aria roles attributes", "keyboard interaction patterns", "focus management", "forms labels errors", "target size 2.5.8".
3. Aplica el checklist estático por archivo mapeado a SC de WCAG 2.2: 1.1.1, 1.3.1, 1.4.3, 1.4.11, 2.1.1, 2.4.3, 2.4.7, 2.5.8 (nuevo en 2.2), 3.3.2, 3.3.3, 3.3.7, 3.3.8, 4.1.2, 4.1.3 y patrones WAI-ARIA (modales, menús).
4. Verifica en runtime con Playwright: asegura el dev server (arranca `npm run dev` en background solo si `localhost:3000` no responde), inyecta **axe-core desde CDN** con `playwright_browser_evaluate` (sin instalar nada), revisa el accessibility snapshot, recorre el orden de foco con Tab y deja las capturas en `.playwright-mcp/`. Si axe-core o el runtime fallan, degrada a checks manuales y dilo en el reporte.
5. **Cada auditoría de una URL externa es autocontenida y se agrupa por dominio → página → run**: guarda TODAS sus evidencias (capturas, `axe-results.json` y `report.md`) en `.playwright-mcp/a11y/<dominio>/<página>/<timestamp>/` (ej.: `https://espanaaudiovisuales.com/home` → `.playwright-mcp/a11y/espanaaudiovisuales.com/home/2026-10-23_143000/`), de modo que varias páginas del mismo dominio quedan como carpetas hermanas bajo el dominio; cada run usa una carpeta nueva con su timestamp y nunca sobrescribe evidencias anteriores.
6. Corrige las violaciones con diffs mínimos solo en targets locales (código en inglés, comentarios en español, convenciones AGENTS.md); para URLs externas emite recomendaciones accionables **en HTML/ARIA genérico** (con hint opcional del stack detectado si lo hay), nunca con suposiciones de React.
7. Ejecuta `npm run lint` y `npx tsc --noEmit` si hubo ediciones; corrige lo que hayas introducido.
8. Cierra el navegador Playwright y detén únicamente el dev server que tú arrancaste.
9. Termina con el reporte por target: modo (fix/report-only), SC revisados, hallazgos por severidad, estado de axe-core, fixes aplicados o recomendaciones, evidencia (ruta de la carpeta autocontenida en URLs externas) y fuentes de Context7 citadas.
